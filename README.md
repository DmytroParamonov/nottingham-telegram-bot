# 🏰 Шериф Ноттінгема — Telegram Bot

Фанатська Telegram-реалізація гри про торгівлю, декларування, контрабанду, хабарі та шерифа. Проєкт не використовує офіційні ілюстрації чи повний текст правил і не є офіційним продуктом правовласників настільної гри.

Інтерфейс бота — **українською мовою**. Термінологія орієнтується на українську локалізацію другої редакції: **дозволені товари, контрабанда, хабар, прилавок, Торгівля, Завантаження товарів, Декларування, Огляд**.

## Поточний режим

Зараз реалізовано стандартну базову гру для **3–5 гравців**.

Шостий гравець поки навмисно не допускається: для шістьох у другій редакції використовуються два заступники шерифа, тайл здобичі та окремі правила огляду. Робити шістьох із одним звичайним шерифом було б неправильно.

## Що вже працює

- 3–5 гравців у груповому чаті;
- кожен отримує 50 золотих і 6 карток;
- окрема колода для гри втрьох: картки з позначкою `4+` вилучаються;
- у грі втрьох кожен стає шерифом 3 рази;
- у грі вчотирьох або вп’ятьох — 2 рази;
- випадковий перший шериф;
- **Торгівля:** шериф обирає першого торговця, далі гравці ходять за годинниковою стрілкою;
- у свій хід торговець може скинути 0–5 карток і добрати руку до 6;
- скинуті картки публічно показуються;
- шериф під час Торгівлі руку не змінює;
- **Завантаження товарів:** у мішок кладеться 1–5 карток;
- після запечатування мішок змінити неможливо;
- **Декларування:** починає гравець ліворуч від шерифа, далі по колу;
- кількість карток декларується точно;
- можна назвати лише один вид дозволеного товару;
- декларація фіксується ботом і більше не змінюється;
- **Огляд:** шериф може оглянути будь-яку кількість мішків у будь-якому порядку або не оглядати жодного;
- пропуск без хабара;
- швидкий грошовий хабар через `/bribe`;
- повний конструктор угод через `/deal`;
- хабар золотом;
- хабар дозволеними товарами з прилавка;
- хабар контрабандою з прилавка;
- хабар товарами зі свого мішка при угоді про пропуск власного мішка;
- блеф щодо виду й кількості обіцяних товарів;
- якщо обіцяного товару реально немає, існуюча частина угоди все одно виконується, а відсутній товар не сплачується;
- третій гравець може заплатити шерифу за пропуск або огляд чужого мішка;
- угода може містити додаткову обов’язкову умову: наприклад, «пропусти мене й оглянь Марка»;
- така додаткова умова виконується ботом у цьому ж раунді й не може бути зламана наступним хабарем;
- майбутні обіцянки через `/promise` записуються, але не примушують гравця виконувати їх у наступному раунді;
- карти з руки не можна використовувати як хабар;
- якщо чесного торговця оглянули — шериф платить штраф за всі картки в мішку;
- якщо торговець збрехав — правильно задекларовані товари лишаються, інші конфіскуються й штрафуються;
- якщо золота не вистачає, борг покривається товарами з прилавка: спочатку дозволеними, потім контрабандою;
- при проході без огляду дозволені товари стають відкритими, а тип успішно провезеної контрабанди залишається таємним;
- наприкінці раунду всі добирають руку до 6 карток;
- автоматичне перемішування скидання, якщо колода закінчилася;
- фінальний рахунок: золото + вартість товарів + бонуси «короля» і «королеви»;
- поділ бонусів при нічиїй з округленням донизу;
- тай-брейки: спочатку кількість дозволених товарів, потім кількість контрабанди;
- SQLite;
- автоматичні тести та GitHub Actions.

## Як працюють угоди

Під час Огляду торговець відкриває `/deal` або кнопку **«🤝 Угоди та хабарі»**.

У конструкторі можна вибрати:

- кого шериф має **пропустити** або **оглянути**;
- скільки заплатити золотом;
- які товари пообіцяти з прилавка;
- які товари пообіцяти зі свого мішка;
- кого ще шериф зобов’язується оглянути в цьому ж раунді;
- майбутню необов’язкову обіцянку.

Після натискання **«📤 Надіслати шерифу»** шериф отримує фінальні умови. Кнопка **«🤝 УГОДА — прийняти»** одразу списує фактичну оплату та виконує всі обов’язкові дії.

Товарами дозволено блефувати. Наприклад, можна пообіцяти 2 яблука, маючи лише одне: якщо шериф погодився, бот передасть одне яблуко й повідомить, що друге було блефом.

### Цифрова адаптація товарів із мішка

Щоб не ламати розрахунок огляду й штрафів, автоматичний хабар **товарами з мішка** використовується тільки в угоді про пропуск власного мішка. Для впливу на чужий мішок можна платити золотом і товарами зі свого прилавка.

Це не заважає живим переговорам у груповому чаті: бот фіксує саме фінальні умови, які сторони погодили.

## Важливі цифрові адаптації

1. **Перший шериф обирається випадково.** У фізичній грі використовується жартівливий критерій із реальною готівкою, який для Telegram не має практичного сенсу.
2. **Порядок Торгівлі зберігається.** Шериф обирає першого торговця, далі хід іде за годинниковою стрілкою; бот не дозволяє перестрибнути чужу чергу.
3. **Сплата штрафного боргу товарами автоматизована.** Бот підбирає комбінацію з мінімальною переплатою, зберігаючи порядок: спочатку дозволені товари, потім контрабанда.
4. **Обов’язкова умова поточного раунду виконується одразу.** Якщо угода вимагає додатково оглянути інший мішок, бот робить цей огляд відразу після головної дії. Це гарантує, що прийняту угоду неможливо порушити випадковою кнопкою.
5. **Майбутні обіцянки не примусові.** Вони зберігаються як текст домовленості, але майбутній шериф може її порушити.

## Чого ще немає

- повноцінних формальних контрпропозицій, які створює сам шериф кнопками; зараз шериф торгується в чаті, а фінальну форму надсилає той, хто платить;
- режиму 6 гравців із двома заступниками;
- королівських товарів;
- чорного ринку;
- опціонального таймера на Огляд;
- режиму 7 карток на руці;
- вилучення 10 випадкових карток на початку партії.

## Швидкий запуск

```bash
git clone https://github.com/DmytroParamonov/nottingham-telegram-bot.git
cd nottingham-telegram-bot
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
nano .env
python main.py
```

`.env`:

```env
BOT_TOKEN=токен_від_BotFather
DATABASE_PATH=data/nottingham.sqlite3
```

## Як грати

1. Кожен гравець відкриває бота в особистому чаті та натискає `/start`.
2. Додайте бота до спільного Telegram-чату.
3. Творець партії пише `/newgame`.
4. Інші пишуть `/join`.
5. Творець запускає гру через `/begin`.
6. Шериф відкриває `/market` і обирає першого торговця; далі бот передає хід за годинниковою стрілкою.
7. Після Торгівлі торговці збирають `/bag` і запечатують мішки.
8. Бот по черзі викликає торговців на Декларування.
9. На Огляді гравці торгуються в групі й фіксують фінальну пропозицію через `/deal`.
10. Для простого грошового хабара можна швидко використати `/bribe 5`.
11. Шериф приймає угоди або відкриває `/inspect` для звичайного рішення по мішках.
12. Після останнього раунду бот автоматично рахує підсумок.

## Команди

### У групі

- `/newgame` — створити лобі
- `/join` — приєднатися
- `/leave` — вийти з лобі
- `/players` — список гравців
- `/begin` — почати партію
- `/status` — стан партії
- `/cancelgame` — скасувати активну партію

### В особистому чаті

- `/start` — меню
- `/market` — Торгівля; для шерифа — вибір першого торговця
- `/hand` — рука
- `/bag` — мішок
- `/deal` — конструктор угоди/складного хабара
- `/promise текст` — додати майбутню обіцянку до чернетки угоди
- `/bribe 5` — швидко запропонувати 5 золотих за власний пропуск
- `/inspect` — панель поточного шерифа
- `/status` — стан партії

## Raspberry Pi / systemd

Приклад `/etc/systemd/system/nottingham-bot.service`:

```ini
[Unit]
Description=Nottingham Telegram Bot
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=pi
WorkingDirectory=/home/pi/nottingham-telegram-bot
ExecStart=/home/pi/nottingham-telegram-bot/.venv/bin/python /home/pi/nottingham-telegram-bot/main.py
Restart=always
RestartSec=3
Environment=PYTHONUNBUFFERED=1

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now nottingham-bot
sudo systemctl status nottingham-bot
```

Якщо користувач Raspberry Pi має інше ім’я, заміни `User=pi` та шляхи.
